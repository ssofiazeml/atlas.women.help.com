АДМИНИСТРАТИВНАЯ БЕЗОПАСНОСТЬ

ВАЖНО

Доступ к административной панели должен иметь только владелец проекта.

Не создавать публичную регистрацию.

Не создавать систему регистрации пользователей.

Не создавать кнопку "Создать аккаунт".

Не создавать возможность самостоятельного получения роли администратора.

====================================================

ТРЕБОВАНИЯ

Использовать отдельную страницу входа администратора.

Например:

/admin

====================================================

ВХОД

Только по заранее заданному адресу электронной почты и паролю.

Администратор создаётся один раз вручную.

====================================================

ОГРАНИЧЕНИЯ

Если пользователь не авторизован:

* административная панель не отображается;
* административные страницы недоступны;
* прямой переход по ссылке невозможен.

====================================================

РОЛИ

На первом этапе существует только одна роль:

Owner

Только владелец проекта может:

* редактировать организации;
* публиковать истории;
* изменять материалы;
* редактировать карту;
* управлять исследованиями;
* управлять разделом цифровой дипломатии;
* управлять индексом стран.

====================================================

БЕЗОПАСНОСТЬ

Не хранить пароль в открытом коде.

Использовать безопасную авторизацию через Supabase Auth.

Отключить регистрацию новых пользователей.

Отключить социальные входы.

Отключить вход через Google.

Отключить вход через Facebook.

Разрешить вход только для заранее созданной учётной записи владельца проекта.

====================================================

АВТОРИЗАЦИЯ

После выхода из аккаунта пользователь должен автоматически терять доступ ко всем административным страницам.

Попытка открыть административные разделы без авторизации должна автоматически перенаправлять на страницу входа.
